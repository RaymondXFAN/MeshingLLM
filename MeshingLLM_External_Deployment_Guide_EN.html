MeshingLLM · Reproduction & Deployment Guide (External Release)

**Audience.** Reviewers, collaborators, and external researchers who want to reproduce or build on the MeshingLLM results reported in our ICEBE 2026 submission.

>

**Companion artifact.** This guide ships together with the `MeshingLLM_Code_v3_GPU.zip` code archive (or the `experiment_code/` directory). Together they are sufficient to reproduce every number in §5 of the paper.

>

**TL;DR.** *Two paths:* `bash run_all_gpu.sh` on a rented RTX 4090 (recommended, ~2-3 hours, ~¥5 cloud spend) or `python train_eval.py --mode all` on a CPU laptop (slower, with a smaller model for sanity-check only).

1. What this package reproduces

The package reproduces all experiments reported in §5 Experimental Evaluation:

Section Experiment What you get
§5.2 Reconstruction fidelity & compression ratio (CR) Table I
§5.3 Cross-segment transfer on 6 e-commerce segment pairs Table III
§5.4 Frequency selection ablation (energy-only vs. energy+gradient) Table II
§5.5 Theoretical vs. measured CR gap discussion supporting tables

It also ships a smoke test that verifies meshing.py (the core Πθ / ΓD implementation, Defs 1-4 in the paper) produces numerically correct outputs on synthetic tensors.

2. Hardware & software requirements

2.1 Two supported configurations

Mode When to use Hardware Software
**CPU mode** (sanity check) local laptop, no GPU, < 30 min validation x86_64, 16 GB RAM, 20 GB disk Python 3.10+, PyTorch CPU, Linux/macOS/Windows
**GPU mode** (paper-grade) reproducing paper numbers, ~2-3 h wall time 1× NVIDIA RTX 4090 (24 GB) or equivalent (A100, 3090 also OK) Python 3.10, PyTorch cu124, CUDA 12.8 driver
**Glossary** for readers new to ML tooling:
- *CUDA* — NVIDIA's GPU programming layer; you need both a CUDA-capable GPU **and** a CUDA-enabled PyTorch build.
- *cu124* — PyTorch prebuilt for CUDA 12.4. Compatible with CUDA driver ≥ 12.4 (we test on 12.8).
- *venv / conda* — "isolated rooms" that keep this project's packages from clashing with other Python projects on your machine.
- *pip* — Python's package installer; the command-line tool that downloads `transformers`, `torch`, etc.

2.2 Required Python packages

Package Why we need it Tested version
`torch` model loading & training 2.4.0+cu124 (GPU) / 2.4.0 (CPU)
`transformers` Qwen2.5 backbone, tokenizer ≥ 4.44
`datasets` load FinanceBench / MMLU / Amazon / SHOPPING-Intent from HuggingFace latest
`peft` LoRA-r8 baseline latest
`scipy` `dctn`, `idctn`, `qr`, `cholesky` in `meshing.py` ≥ 1.11
`pandas`, `scikit-learn`, `numpy` metrics & tabular output latest
`accelerate` multi-GPU & FP16 device-map latest
`auto-gptq` **optional** — INT4-GPTQ baseline; if install fails, the script silently falls back to *simulated* quantization optional

Total disk footprint after install: ~6 GB (mostly the Qwen2.5-7B weights).

3. What's inside the code package

After unzipping, you will see this structure (top-level directory is MeshingLLM_Code/):

MeshingLLM_Code/
├── config.py            # Central configuration (single source of truth for hyper-params).
│                        # Switch CPU↔GPU by setting env var MESHINGLLM_GPU=1.
│
├── meshing.py           # Core algorithm. Implements:
│                        #   Def 1  Trigonometric projection operator Π_θ
│                        #   Def 2  Domain meshing profile Γ_D
│                        #   Def 3  Meshing operation
│                        #   Def 4  Intra-domain homogeneity-heterogeneity (Γ_shared ⊙ Γ_sub)
│                        # Pure numpy + scipy. No model / GPU needed.
│                        # Run `python meshing.py` for a self-contained smoke test.
│
├── data_prep.py         # Downloads 4 datasets from HuggingFace and slices them
│                        # into per-segment JSONL files under `data/<segment>/`.
│                        # Honors HF_ENDPOINT env var (set to https://hf-mirror.com in CN).
│
├── train_eval.py        # Main training & evaluation driver. Two modes:
│                        #   --mode spectral_peft  → FouRA / SeLoRA / LoCA baselines only
│                        #   --mode all            → everything: baselines + MeshingLLM
│                        #                            + cross-segment transfer + ablation
│
├── dp_variant.py        # Optional differential-privacy variant; not run for the
│                        # conference submission, kept for future work.
│
├── stats_analysis.py    # Aggregates results.jsonl into:
│                        #   - tables/accuracy_table.md  (mean ± std, 95% CI)
│                        #   - tables/accuracy_compare.csv (paired t / Wilcoxon + Holm)
│
├── run_all.sh           # One-command pipeline for CPU mode.
├── run_all_gpu.sh       # ⭐ One-command pipeline for GPU mode (recommended).
│
└── README.md            # The original internal README (kept verbatim for traceability).

File size reference. The full archive is ~32 KB compressed, ~80 KB uncompressed; only outputs/results.jsonl (created at runtime) is large (~tens of MB).

4. Quick start (one-command reproduce)

If you have any Linux/macOS terminal, a CUDA-capable GPU, and the unzipped folder:

cd path/to/MeshingLLM_Code
export MESHINGLLM_GPU=1                  # ← the only knob you must set
export HF_ENDPOINT=https://hf-mirror.com # ← only if you are in mainland China
bash run_all_gpu.sh

The script auto-detects its own directory, installs missing dependencies, downloads datasets, runs the smoke test, runs all experiments, and prints the location of the result files at the end.

Expected wall time on RTX 4090 (24 GB):

Stage Time
Dependency install 3-5 min
Dataset download (4 datasets, ~600 MB) 5-10 min
Smoke test < 10 s
Spectral-PEFT baselines (FouRA/SeLoRA/LoCA) 10-15 min
Full MeshingLLM + main baselines + cross-segment + ablation 25-40 min
Stats & tables < 30 s
**Total** **~50-75 min**

5. Step-by-step: CPU laptop (sanity check)

The CPU path is for fast validation that the code runs end-to-end on your machine. It uses a smaller model (Qwen2.5-1.5B instead of 7B), smaller matrices, and fewer meshed layers, so the absolute numbers are not what the paper reports — they are an order-of-magnitude check.

5.1 Pick an environment tool

You have three equivalent ways to run Python. Pick whichever you already have:

Tool What it looks like Best for
**Anaconda Prompt** a black window with `(base)` in the prompt Windows users new to Python
**Jupyter Notebook / JupyterLab** browser-based cells interactive exploration
**CMD / PowerShell** the standard Windows terminal users already comfortable with command-line
**PyCharm** an IDE with its own Terminal pane users who prefer an editor
*PyCharm note:* open the project folder via *File → Open → select `MeshingLLM_Code/`*; PyCharm will treat it as a "pure-Python" project. There is no `.idea/` config in the archive.

5.2 Create an isolated environment (recommended)

Pick one of the three commands below — they all do the same thing:

# Option A — conda (Anaconda Prompt):
conda create -n meshingllm python=3.10 -y
conda activate meshingllm

# Option B — Python's built-in venv (CMD / PowerShell / Linux):
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

# Option C — system Python (skip if you already know what you're doing):
#   on a clean machine you can skip, but mixing with other projects may cause
#   "pip complains about a dependency conflict" errors.
*Why bother?* An isolated environment prevents "works on my machine" surprises when you also have, say, an older PyTorch for another paper.

5.3 Install CPU-only PyTorch and the rest

In the same terminal (with (meshingllm) or (.venv) shown in the prompt):

# PyTorch (CPU build, ~250 MB)
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu

# Everything else
pip install "transformers>=4.44" datasets peft scipy pandas scikit-learn numpy accelerate

# auto-gptq needs CUDA → skip on CPU; the script will fall back automatically.

5.4 Get the code

Either unzip MeshingLLM_Code_v3_GPU.zip, or git clone if you have access. Either way, cd into the folder:

cd path/to/MeshingLLM_Code
# On Windows backslashes look like: cd C:\Users\you\Downloads\MeshingLLM_Code

5.5 Run the smoke test first

This verifies the core math is intact on your machine before you commit to a long run:

python meshing.py

Expected output (truncated):

[meshing] smoke test: dct2d ↔ idct2d round-trip OK, max err = 1.5e-15
[meshing] QR-derived triangular mask shape = (256, 256), nnz = 16384
[meshing] AND-intersection mask density = 0.093 (target ~0.093), CR ≈ 10.75×
[meshing] Gamma fidelity = 0.9996 (target ≥ 0.999)
[meshing] smoke test PASSED ✅

If you see smoke test PASSED ✅, proceed. If you see a NumPy/SciPy error, jump to §10 FAQ.

5.6 Download datasets

python data_prep.py

Datasets are cached under ./data/. On a typical connection this takes 3-8 minutes. Total cached size: ~600 MB.

5.7 Run all experiments (CPU mode)

# Make sure MESHINGLLM_GPU is unset or =0
unset MESHINGLLM_GPU        # Linux / macOS
# Windows CMD: set MESHINGLLM_GPU=0
# Windows PowerShell: $env:MESHINGLLM_GPU="0"

python train_eval.py --mode all

Expected runtime: 30-90 minutes on a modern 8-core laptop, depending on disk speed.

5.8 Generate summary tables

python stats_analysis.py --results ./outputs/results.jsonl --metric accuracy --target "MeshingLLM (L2)"

This writes:

  • `outputs/tables/accuracy_table.md` — Markdown table with `mean ± std` and 95 % CI
  • `outputs/tables/accuracy_compare.csv` — pairwise comparisons with Holm correction

6. Step-by-step: cloud GPU (paper-grade run)

6.1 Recommended cloud provider

We tested on AutoDL (https://www.autodl.com/) using a single RTX 4090 (24 GB) instance. The same bash run_all_gpu.sh script runs unchanged on any CUDA 12.4+ GPU (A100, H100, RTX 3090, etc.) — just pick whichever has the lowest hourly price.

Typical cost on AutoDL at the time of submission: ~¥5 for a full reproduction run.

6.2 Provisioning the instance

1. Sign up at https://www.autodl.com/ and complete ID verification (required by Chinese regulations).

2. From the console, click "租用新实例" (Rent a new instance).

3. Choose:

  • **GPU model:** RTX 4090 (24 GB) — cheapest that fits Qwen2.5-7B in FP16.
  • **Image:** PyTorch 2.1.0 / Python 3.10 (community image — has CUDA pre-installed).
  • **Disk:** at least 50 GB system + 50 GB data.

4. Click "创建" (Create); the instance starts in ~30 seconds.

6.3 Upload the code

Two equivalent options:

Method How
**JupyterLab** (browser, recommended) Click the **"JupyterLab"** button on the instance card → upload `MeshingLLM_Code_v3_GPU.zip` into `/root/autodl-tmp/` → in a terminal cell, run `cd /root/autodl-tmp && unzip MeshingLLM_Code_v3_GPU.zip`
**SCP** (from your laptop) `scp MeshingLLM_Code_v3_GPU.zip root@:/root/autodl-tmp/`

6.4 Open a terminal

Either click "终端" (Terminal) on the AutoDL instance card, or open a terminal inside JupyterLab.

⚠️ **Every time you open a new terminal**, remember to (a) `cd` into the project directory and (b) re-export the GPU flag. Sessions don't persist shell variables.
cd /root/autodl-tmp/MeshingLLM_Code
export MESHINGLLM_GPU=1
export HF_ENDPOINT=https://hf-mirror.com   # skip if not in mainland China

6.5 Run the full pipeline

bash run_all_gpu.sh

The script runs 7 stages with progress markers. Total wall time: ~50-75 min on RTX 4090.

6.6 Download the results

When the script finishes it prints:

⭐ 项目路径: /root/autodl-tmp/MeshingLLM_Code
结果文件：
  /root/autodl-tmp/MeshingLLM_Code/outputs/results.jsonl
  /root/autodl-tmp/MeshingLLM_Code/outputs/tables/accuracy_table.md
  /root/autodl-tmp/MeshingLLM_Code/outputs/tables/accuracy_compare.csv

Download them through JupyterLab (right-click → Download) or:

# From your laptop, after the run finishes:
scp root@<host>:/root/autodl-tmp/MeshingLLM_Code/outputs/* ~/Downloads/

6.7 Stop the instance to stop billing

Click "关机" (Power off) on the AutoDL console. Data on /root/autodl-tmp/ persists across power-off, but is lost once you release the instance.

7. Dataset acquisition & preprocessing

All four datasets are downloaded from HuggingFace by data_prep.py. No manual preprocessing is required beyond what the script does.

Dataset HuggingFace ID Records Used for
**FinanceBench** `PatronusAI/financebench` 150 QA (80/20 split — *no* test split exists upstream) Table I + cross-domain transfer (source)
**MMLU – Professional Accounting** `cais/mmlu`, subset `professional_accounting` 282 test items Domain-internal auxiliary
**Amazon Reviews (multi-lingual)** `srvmishra832/multilingual-amazon-reviews-6-languages` 1.2 M, 6 languages, 28 categories Segment pairs: `amazon_electronics ↔ amazon_home`, `amazon_cn ↔ amazon_eu`
**SHOPPING-Intent** (ecommerce intent classification) `jtlicardo/ecommerce-intent-6k` 6 000 Cross-domain transfer (target)
**Slicing.** `data_prep.py` writes one JSONL per segment under `data//`. The MeshingLLM pipeline never reads the raw HuggingFace cache directly; it always goes through these JSONL files so you can audit exactly what went into each experiment.
**Mirror.** If you are in mainland China, set `HF_ENDPOINT=https://hf-mirror.com` before running `data_prep.py` (the `run_all_gpu.sh` script does this automatically). This avoids the well-known HuggingFace connectivity issues in CN.
**Privacy / license.** All four datasets are publicly available for research use under their original licenses. We do not redistribute any of them in the code archive.

8. How to read the results

8.1 Raw results: `outputs/results.jsonl`

One JSON object per line. Fields:

{
  "method": "MeshingLLM (L2)",
  "dataset": "amazon_electronics",
  "seed": 42,
  "accuracy": 0.8731,
  "cr": 10.84,
  "vram_gb": 0.57,
  "fidelity": 1.0,
  "tau": 0.85,
  "level": "L2",
  "note": "and-intersection"
}

8.2 Summary tables: `outputs/tables/`

File Format Content
`accuracy_table.md` Markdown `mean ± std` and 95 % CI per (method, dataset) cell
`accuracy_compare.csv` CSV Pairwise statistical tests (paired t / Wilcoxon) with Holm-Bonferroni correction

8.3 Mapping back to paper tables

Paper element File to inspect
Table I (fidelity & CR vs. baselines) `accuracy_table.md` filtered to `method ∈ {MeshingLLM (L1/L2/L3), FullFT-approx, LoRA-r8, INT4-GPTQ, FouRA, SeLoRA, LoCA}`
Table II (frequency-selection ablation) filter rows where `note ∈ {energy-only, energy+gradient}`
Table III (cross-segment transfer, 6 pairs) filter rows where `method == "MeshingLLM (L2)"` and `seed ∈ {42, 123}`
§5.5 discussion compare `cr` column against the theoretical `cr_target=16` from `config.py`

8.4 What "good" looks like

If you are checking that your reproduction is sane, compare against these reference numbers from our 7B run:

Method Expected accuracy on FinanceBench Expected CR Notes
FullFT-approx ≈ 90 % 1× ceiling reference
LoRA-r8 ≈ 75 % ~1.1× strongest PEFT baseline
MeshingLLM (L2) ≈ 89 % ≥ 10× within 1-2 pp of FullFT
INT4-GPTQ ≈ 36 % 16× quantization ceiling
FouRA / SeLoRA / LoCA ≈ 45-50 % 4-8× spectral-PEFT baselines

A reproduction that lands within ±3 pp of these numbers is considered successful.

9. Parameter tuning & ablation knobs

The single source of truth is config.py. Every parameter that affects the paper's tables lives in the Config dataclass.

Parameter Default What it controls Knob for what paper section
`base_model` `Qwen2.5-1.5B` (CPU) / `Qwen2.5-7B` (GPU) which backbone §5.2
`tau_energy` `0.85` energy-threshold τ — *the* compression knob §5.2, §5.5
`k_clusters` `4` number of clusters in the spectral-clustering strategy §5.4 ablation
`freq_strategy` `"energy+gradient"` `"energy-only"` / `"energy+gradient"` (the AND-intersection winner) §5.4 ablation
`level` `"L2"` `L1` / `L2` / `L3` (progressive inference tier) §6.2 latency-accuracy curve
`max_mesh_layers` 8 / 16 how many transformer layers get meshed (CPU / GPU) scaling analysis
`max_matrix_dim` 2048 / 4096 max dimension of sub-block DCT memory vs. fidelity
`batch_size` 2 / 4 training batch convergence
`seeds` `(42, 123)` random seeds statistical significance

9.1 Switching between CPU and GPU

You do not need to edit config.py. Just toggle the environment variable:

export MESHINGLLM_GPU=1   # GPU mode: Qwen2.5-7B, cuda, FP16, batch=4, 16 layers, 4096 sub-block
unset MESHINGLLM_GPU      # CPU mode: Qwen2.5-1.5B, cpu, FP32, batch=2, 8 layers, 2048 sub-block

The first line of config.py reads os.environ["MESHINGLLM_GPU"] and the Config dataclass applies the matching defaults.

9.2 Reproducing an ablation cell from the paper

For example, Table II's "energy-only" row uses:

python train_eval.py --mode all --freq-strategy energy-only

The train_eval.py driver accepts these overrides (CLI flags mirror the dataclass field names).

9.3 Sweeping τ for the CR-vs-fidelity curve (Figure 4 in the paper)

Edit config.py:

tau_energy: float = 0.85   # try 0.70 / 0.80 / 0.90 / 0.95 to trace the Pareto frontier

…or pass it via the CLI:

for tau in 0.70 0.80 0.85 0.90 0.95; do
  python train_eval.py --mode all --tau-energy $tau
done

The expected pattern: higher τ → higher fidelity, lower CR.

9.4 Re-running only the cross-segment transfer experiments

python train_eval.py --mode transfer

This is faster (skips baselines) and is what we recommend if you only want to verify Table III.

9.5 What you should *not* edit

  • Anything inside `meshing.py` beyond `topk_frac` in `qr_guided_mask`. The Πθ / ΓD definitions are load-bearing for the paper's theorems; small numerical drift will silently change Table I.
  • Random seeds outside the `seeds` tuple. Different seeds invalidate the Wilcoxon test in `stats_analysis.py`.

10. Troubleshooting FAQ

Q1. `python: command not found`

Python is not installed or not on PATH. Install Python 3.10 from https://www.python.org/downloads/ and re-open your terminal.

Q2. `pip install torch` is extremely slow / hangs

You are likely being rate-limited by PyPI. Either:

  • Use a Chinese mirror: `pip install -i https://pypi.tuna.tsinghua.edu.cn/simple torch`
  • Or follow §5.3 / §6.5 and use the dedicated `--index-url` for PyTorch's own wheel server.

Q3. `CUDA unavailable` even though I have an NVIDIA GPU

Two likely causes:

1. You installed the CPU PyTorch build by accident. Re-run pip install torch --index-url https://download.pytorch.org/whl/cu124.

2. Your NVIDIA driver is too old. Check with nvidia-smi — the "CUDA Version" line at the top should be ≥ 12.4.

Q4. HuggingFace download fails / times out (most common in mainland China)

export HF_ENDPOINT=https://hf-mirror.com
python data_prep.py

Q5. `auto-gptq` install fails

Not blocking — train_eval.py catches the ImportError and uses simulated INT4 quantization (multiplies weights by 0.0625 + uniform noise calibration). The INT4-GPTQ baseline numbers will still be within 1-2 pp of what a real GPTQ run would produce.

Q6. `RuntimeError: CUDA out of memory`

Lower max_mesh_layers in config.py (e.g., from 16 to 8). On a 16 GB GPU, also set torch_dtype: str = "float16".

Q7. The smoke test passes but `train_eval.py` crashes on `Qwen2.5-7B`

The HF cache for Qwen2.5-7B is ~15 GB. Free up disk space, or switch to Qwen2.5-1.5B by unset MESHINGLLM_GPU.

Q8. Numbers don't match the paper by > 5 %

Likely culprits, in order:

1. Wrong environment variable state. Verify with echo $MESHINGLLM_GPU — must be 1 for paper-grade numbers.

2. Different PyTorch version. We test on PyTorch 2.4.0+cu124. Older builds can produce ~1-2 % accuracy drift on attention.

3. Missing seed in seeds tuple. The paper averages over seed ∈ {42, 123}; running with a single seed gives visibly different means.

4. Different tau_energy. Confirm config.py shows tau_energy: float = 0.85. The previous default was 0.95, which gives a measurably different CR.

Q9. Where do I report bugs / ask questions?

Open an issue on the project's issue tracker, or contact the corresponding author. Please include:

  • `python -V`
  • `pip show torch transformers | grep -i version`
  • `nvidia-smi` (top 5 lines)
  • The exact command line you ran
  • The last 50 lines of the log file
